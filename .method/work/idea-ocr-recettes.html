Idée backlog : OCR local de recettes

Pitch
Intégrer un modèle d'OCR local pour prendre en photo une recette (livre, magazine, manuscrit) et faire formaliser l'app automatiquement au format interne (sections ingrédients / étapes / quantités / temps). Raison du local : pas d'appel cloud — données personnelles, offline-first, latence.
Candidats
Tesseract 5 (baseline multilingue FR/EN/IT/ES), PaddleOCR (texte imprimé structuré), EasyOCR (intégration rapide), Florence-2 / TrOCR (robustesse manuscrits).
Pipeline pressenti
capture photo, pré-traitement (deskew, denoise, détection de zones), OCR brut, parsing structurant (petit LLM local type Phi-3 mini ou regex + modèles), validation UI, sauvegarde au format MaestroPesto.
Dépendances
Format de recette interne (lib/core/models), choix du modèle OCR (perf/RAM), choix du parseur structurant. Origine : Gui, session du 2026-08-22.
Prochain pas
Cadrer un work package dédié (critères, périmètre, décision de lancement PO) avant tout code.
